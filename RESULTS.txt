SM90: every Dense/SOL pair has identical per-rank input hashes and parallel
configuration; finite outputs and unchanged inputs after replay. All six
within-run CV values are below 0.16%. These are single-load repeated-call
measurements, not an independent multi-launch or multi-host stability study.
GH200 96GB uses model-level CPU offload for capacity. Transfers occur before
the measured DiT; its full weights remain resident for all repeated calls.
GB200 uses no offload. Compare backends within each hardware configuration.

SM100: all SOL cases produced zero completed forward samples. Python stacks
on both ranks remain at block index 49 in _merge_sol_bsa_residual, chunk
9984:10240. A Ref2VA CUDA_LAUNCH_BLOCKING=1 diagnostic locates a blocking
cuDNN block64 CuTe DSL BSA launch. Root cause is not established.
CUDA_DEVICE_MAX_CONNECTIONS=1 and an external use_clc=False diagnostic did
not resolve the stall. They are separate diagnostic runs, not default results.
The max-connections Dense control median is 4.999s; input/output hashes
match the default Dense control. No timeout duration is treated as latency.

Reproduction: copy reproduce/ to /work/bundle in the pinned image with
exactly two visible NVLink GPUs, host IPC and 300+ GiB checkpoint cache.
Run: bash /work/bundle/bootstrap.sh /work
Existing prepared environment: bash /work/bundle/run_forward.sh /work
The default script stops at failures and has no per-case timeout.
For the GB200 remaining T2VA/FL2VA cases after stopping stalled Ref2VA:
  bash /work/bundle/run_remaining.sh /work
That script records a 300s process timeout per case, including model loading.
Use fresh result directories; the harness refuses existing rank reports.
The intentional H3_FORWARD_BENCHMARK_COMPLETE exception ends successful
measurements before sampler advancement and VAE decoding. Success requires
two complete rank reports, not just that exception string.

The exact original SM120 harness was not supplied. This reconstructs its
stated protocol and retains first-three medians, but does not independently
reproduce or supersede that user-provided table.
SM103 was not tested. No video/audio outputs, SSIM, PSNR, LPIPS, HTTP serving,
or end-to-end speedup were measured. No production kernel workaround was
added to the PR. Redacted logs, individual samples, input hashes, protocols
and environment manifests are stored beside this report.
