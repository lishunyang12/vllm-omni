This deliberately reuses the existing C design, including A's protected-Q
route bypass, and adds only the common four pooling casts. Against the fixed
#594 baseline the sole changed package file is sm100/mainloop.py. Historical
unfixed-pooling validation is not treated as acceptance. No GPU work was done.

Concrete reduction
  Original exact K gather issues four64x64 BF16 TMA copies per pair; V also
  issues four. Protected Q selects every valid KV block in ascending order.
  The candidate uses one full128x128 TMA for K and one for V on complete pairs:
  eight source-level TMA copy issues become two (75% fewer), with identical
  transferred bytes. It also retains A's removal of needless route work for
  those protected query CTAs. This targets the single producer warp's work.
  Actual lowered instruction counts and register/spill effects still need GPU
  compilation; no speedup is inferred merely from source instruction counts.

Correctness/resource boundaries
  G256 starts are multiples of256 blocks. Thus pair starts are even and the
  full-tile coordinate block0//2 addresses exactly block0 and block0+1.
  Unprotected queries keep arbitrary gathered pairs. An unpaired final block
  keeps the original duplicated/masked fallback. A paired partial token tail
  relies on the existing descriptor zero-fill and unchanged valid-token masks.
  The protected predicate is read from the device mask each launch, preserving
  graph mask updates. No constant-mask specialization is added.
  Existing canonical K/V shared layouts, producer acquisitions, barrier byte
  expectations, completion-backed releases and MMA/softmax order are preserved.
  SharedStorage and NamedBarrier/PipelineTmaUmma constructor ASTs match baseline;
  no SMEM/TMEM storage or stages are added. Two extra descriptors/prefetches and
  extra branch/address live ranges remain resource risks. The reduction may be
  hidden behind the exact MMA/softmax critical path; this needs measurement.
