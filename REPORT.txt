H3 Ref2VA: direct upstream SOL on SM90, SM100 and SM120

Same official 768p/5s request, reference assets, seed 0, checkpoint and source pins.
BF16, eager, TP1. Three warmup pairs + nine measured pairs, alternating order.
Each sample is a synchronized full 50-layer first-step DiT forward; maximum
wall latency across ranks. Reported speedup is the ratio of the two medians.
The harness then stops before denoising progression or VAE decoding.

All nine measured pairs are faster in each primary result. Raw rank reports
and sample ranges are linked by comparison.json; comparison.csv is machine-readable.

SM90/SM100 use two GPUs with Ulysses2. SM120 uses one GPU/Ulysses1.
CPU offload is equal for Dense and SOL on SM90/SM120 for capacity, with
weights resident inside the measured forward. SM100 does not use offload.
Compare each configuration against its own Dense baseline. GPU counts,
products and power/clock policies differ; this is not an architecture ranking.
Encoder-generated DiT input values differ across architectures. Each
machine replays identical inputs for its own Dense/SOL pairs.

Repetition and stability:
  SM90: final Dense 10.752560s / SOL 6.555892s. An earlier independent
  process before mask-alignment hardening measured 10.745810s / 6.561000s;
  both input hashes and each implementation's outputs matched.
  SM100: primary fresh processes measured 7.585841s / 7.104273s (1.0678x)
  and 7.562043s / 7.104617s (1.0644x). Inputs and each implementation's
  outputs match byte-for-byte across these processes and ranks.
  Two additional diagnostic processes retain separate raw samples.
  SM120: one complete 3+9-pair run. A first attempt was stopped after
  warmup to raise its insufficient 30-minute launcher budget; excluded.
  Every architecture has finite and byte-identical first/last outputs
  within each implementation. Stability is scoped to this request/step.

SM100 hardware qualification:
  Default-node results show a modest reproducible full-forward gain.
  GPU0 Dense ran at a sampled median 892 MHz with a power-cap flag active
  in all 199 polls, versus SOL at median 1200 MHz. Per-rank profile shows
  substantial Dense imbalance. The initial Slurm frequency-control request
  was unavailable. A later follow-up used explicitly delegated nvidia-smi
  and completed controlled runs: SOL is about 22% slower at 600/750 MHz.
  See power-followup/REPORT.txt for the new evidence and restored clocks.
  See sm100/profile/INTERPRETATION.txt, raw telemetry and kernel summaries.
