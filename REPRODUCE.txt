H3 Ref2VA: full forward Dense cuDNN versus direct upstream SOL

This measures the first conditional denoising step, all 50 DiT layers, then
intentionally stops before sampler advancement and VAE decode. It does not
measure HTTP latency, complete video generation, SSIM, PSNR or LPIPS.

Image:
  vllm/vllm-openai:cu134-nightly-1648fefab91204f3b15bf8062217316f07f2c4bb
Omni measured source: 3da353c45224f5863808da320d694be045c16ef8
SOL dependency: 088897e0c6a9cb970f00b43ab2177c3be7336b36
Checkpoint: MiniMaxAI/MiniMax-H3@0919fb684102ef115126612f3fbb84d1027e7317
Request: the included official Ref2VA request, seed 0, 768 short edge, 5s/24fps.
Request and reference asset SHA256 values are in reproduce/input-manifest.json.
The harness rejects changed assets or a changed request.

Hardware configurations:
  SM90:  2x GH200 96GB, TP1/Ulysses2, model CPU offload for capacity.
  SM100: 2x GB200, TP1/Ulysses2, no model CPU offload.
  SM120: 1x RTX 6000D (83.05 GiB visible), TP1/Ulysses1, model CPU offload.
Provide enough host memory (at least 224 GiB for the single-GPU configuration)
and checkpoint/cache space (350 GiB recommended). The scripts reuse the HF cache
and never evict it. Check platform compatibility with the selected image.

Example with Docker; keep the same container for bootstrap and measurement:

  export H3_WORK=/absolute/path/to/h3-sol-test
  mkdir -p "$H3_WORK/native"
  cp -R reproduce/. "$H3_WORK/native/"
  docker run -d --name h3-sol-native --gpus '"device=0,1"' --ipc=host \
    --mount type=bind,source="$H3_WORK",target=/work --entrypoint bash \
    vllm/vllm-openai:cu134-nightly-1648fefab91204f3b15bf8062217316f07f2c4bb \
    -c 'sleep infinity'
  docker exec h3-sol-native bash /work/native/bootstrap.sh /work
  docker exec -e H3_GPU_COUNT=2 -e H3_RUN_ID=1 h3-sol-native \
    bash /work/native/run.sh /work
  docker exec -e H3_GPU_COUNT=2 -e H3_RUN_ID=2 h3-sol-native \
    bash /work/native/run.sh /work

For single-GPU SM120, expose device=0 and set H3_GPU_COUNT=1 in both run commands.
Allow at least 60 minutes per SM120 run, including initialization and warmup;
do not reduce the workload or sample count to fit a short launcher timeout.
Use a new H3_RUN_ID each time. Existing rank reports are rejected to prevent
mixing fresh measurements with stale results.

Bootstrap installs immutable source archives, preserves the image's
PyTorch/vLLM/CUDA stack, installs validated Python constraints and downloads
only Ref2VA. Empty-cache provisioning was executed successfully on the SM100
and SM120 machines. Installed environments are included with the evidence.

Each run starts a fresh model process. Three warmup pairs precede nine measured
pairs, with Dense/SOL order alternating. The report uses synchronized maximum
wall latency across ranks for each complete 50-layer forward, then its median.
Dense uses CuDNNAttentionImpl through the same SOL objects' dense guard; SOL
uses the production upstream sparse path. Both use BF16 and eager execution.
CPU offload is enabled equally for Dense/SOL where capacity requires it; model
weights are resident inside the measured boundary. Output tensor copies, hash
checks, and optional profiling occur outside the timed samples.

Within each machine, Dense and SOL replay the identical DiT input tensors.
Across architectures, the request, assets, seed, shapes and checkpoint match,
but encoder-produced tensor values can differ numerically. Compare each
machine's own Dense-to-SOL ratio. Different GPU counts and products make the
absolute latency columns unsuitable for architecture ranking.

Recompute statistics directly from per-rank reports (no Torch required):

  python3 /work/native/summarize.py /work/results/ref2va-native-1 \
    /work/results/ref2va-native-2 --output /work/results/recomputed.json

Check forward tensor error and repeated-process equality with FP64 analysis:

  docker exec -e OMP_NUM_THREADS=2 h3-sol-native python3 \
    /work/native/compare_outputs.py /work/results/ref2va-native-1 \
    /work/results/ref2va-native-2 --cross-process \
    --output /work/results/output-comparison.json

Optional profiling in a separate fresh process:

  docker exec -e H3_GPU_COUNT=2 -e H3_RUN_ID=profile -e H3_PROFILE_AFTER=1 \
    h3-sol-native bash /work/native/run.sh /work

Profiling runs one Dense and one SOL full forward AFTER all 3+9 paired calls
and output captures. It produces per-rank Chrome traces and operator tables.
Profile timings have instrumentation overhead; use the unprofiled summary for
speedup. Check that profile-complete-rank-N exists for every rank. This optional
path was executed on SM100, not on SM90/SM120.

Production serving only needs --diffusion-attention-backend SOL_ATTN; no
provider/native flag is accepted. The benchmark patch is only instrumentation
and dense/sparse switching; it is not a production model implementation.
